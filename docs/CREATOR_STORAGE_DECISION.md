# Creator V1 storage decision

Existing hosting is static GitHub Pages; the repository has no deployed Firebase/Auth/Firestore/API adapter. No new service/project/account, cloud resource, billing or hosting change was made.

V1 uses a validated, versioned, self-contained URL fragment on the real static `/p/` page. The fragment is processed in the browser rather than sent in the HTTP request ([MDN](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment)); GitHub Pages serves the fixed file ([GitHub publishing documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)). Small quiz links therefore work in another browser with no backend, storage quota or public-write API. Tests open a fresh page/context and exercise the friend result/create-own loop. Link payload capped at 1,800 base64url characters, decoded JSON strictly validated, known fields only, Unicode decoding checked, text rendered with textContent. UI caps 1–8 questions, title 60, question 120, option 60 characters. A payload exceeding the link cap is rejected with a shorter-content instruction; local preview remains available.

The draft is stored only in the existing safe versioned browser adapter. Storage denial/quota failure does not block preview or link creation; the UI reports unsaved drafts. No title/question/answer/link is sent through analytics.

This is a casual share-link product, not server publication. Anyone with the full link can decode answers or alter the payload; score is local and non-authoritative. There is no private quiz, owner authentication, revocation, shared mutable record, server ranking, link recovery or dynamic OG image. The UI states the relevant limitations. Encoding is not encryption. The fixed player page is noindex and excluded from sitemap; user content is never server-rendered.

Server-persisted UGC, private answers, moderation and authoritative scores are **not implemented**. They require a separately reviewed identity/rules/quota/abuse architecture and an explicitly selected service. No unconfigured “free tier” is assumed reliable or provisioned. Dynamic OG and short opaque server IDs remain future hosting requirements. Any solution requiring payment/billing is a report-only suggestion under the guardrail. Existing Pages limits still apply ([GitHub limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)).
